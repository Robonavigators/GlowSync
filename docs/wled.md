# WLED connection

GlowSync can discover mDNS HTTP service candidates and checks `/json/info` before listing a controller as verified. Manual IP address or hostname entry is available when discovery is blocked. Editing the address invalidates pending verification and replaces the previous status with a reminder to test the new address. Enter a plain address such as `192.168.0.42` or `wled.local`, not a URL: schemes, ports, paths, queries, fragments and whitespace are rejected before verification. Manual LED test buttons, including the setup wizard's LED marker, require a nonblank controller address and are unavailable during active sync; the UDP sender also rejects blank and URL-style destinations before DNS resolution. A UDP send still does not verify delivery. Multiple verified controllers can be saved; one controller is streamed to during a capture session. Change the destination by starting a new session.

The app sends RGB24 DDP over unicast UDP port 4048. Frames are divided into packets with byte offsets; the final packet has the PUSH flag. DDP and the controller's HTTP API are unencrypted, so use a trusted network. A successful HTTP check confirms that the information endpoint responded; a UDP send confirms only that the local send call completed, not that LEDs received or displayed the frame.

GlowSync checks controller HTTP reachability on a separate low-frequency control worker and retries local network errors with backoff. UDP cannot detect every unreachable or restarted controller. See [TROUBLESHOOTING.md](TROUBLESHOOTING.md) for network checks.
